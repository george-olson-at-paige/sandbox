# Stack review — how a stack behaves (opened 2026-10-29)

A requirements pass with George on the stack pattern: the list under a Vault item that holds people (later records), how someone is added (pick from the book, quick add by kinship or role, someone new), removed, and what we ask about each person. The spec is ADR 0076's *Amendment (2026-10-28): how a stack behaves*, rules 1–7 (`lookup-keys` worktree, `docs/decisions/0076-vault-page-concepts.md`); the breakdown and the first decisions are `agents/docs/stack-add-pattern-plan-2026-10-28.md` there. Built in `packages/ui/src/vault/` (`stack-rules.ts` and the stack components), reviewed in Storybook on http://localhost:6107 (Vault › PeopleStack and its parts).

Same rules as the REVIEW-* passes: a held list, IDs `S-nn` never reused, status open → approved / changed → built → verified, plus deferred. Each row says who decides: **George** (product or design) or **Eng**. A decision that changes a rule names the ADR rule it touches, so the main session can amend ADR 0076 and port it to the Vue Stack.

**Where things stand** (2026-10-29, on `spike/stack-add` after `148c2c11d`): typecheck clean; lint 1 error, the known one in `forms/fields/address-field.stories.tsx` (the paused agent's file, not ours), 6 warnings; 245/245 node tests; `npm run check` clean; stack plays 65/65 with `--a11y`.
