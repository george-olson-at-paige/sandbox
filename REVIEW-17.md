# Review 17 — Storybook organization, and code quality (opened 2026-10-21)

Two read-only reviews George asked for after REVIEW-16: how Storybook is organized, and the quality and maintainability of the code. Same rules as earlier rounds: a held list, IDs `R17-nn` never reused, statuses → built → verified, plus deferred. **George agreed the recommendations and the spike fixes (2026-10-21); built the same day** (R17-15–R17-19 carry to the real package). Verified at the end: typecheck, lint (0 errors, the 6 dag-frame warnings), 231 node tests, `npm run check` (tokens, layers, 129 entry points, 10 scripts), 758 plays, every admin route 200 on 3105. Each row says who decides: **George** (product or design) or **Eng** (an engineering call, ours to make), and a rough size.

**Where things stand** (2026-10-21): typecheck clean in both workspaces; `npm run check` 0 findings (layers, 123 entry points, tokens in Paige code); 221/221 node tests; lint 0 errors, 6 deliberate warnings in `dag-frame.tsx`; plays 49/49 for the admin lists. Live Storybook: 763 stories and 139 docs pages in 12 sections.

**Verdicts.** *Storybook:* the structure is sound (the folder is the section, no `title:` lines, the layer order enforced, no component in the wrong section); the weak spots are Admin's page stories, the copied fixtures, two components without a docs page, and stale Overview pages and sort lists. *Code:* good for a prototype and mostly worth carrying over; the weak spots share one cause, slices built one after another without pulling out what they share (formatters, types, fixtures, screen boilerplate), plus checks that run only by hand and a CLAUDE.md that has outgrown its job.
