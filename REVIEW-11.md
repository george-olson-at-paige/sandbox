| R11-04 | [4] Fix InlineEdit: show the switch within the page; revisit it — the buttons are too big and maybe should go under, which suits desktop and mobile. The agent studies how mature systems do inline editing (Atlassian's inline edit, GitHub's in-place edits, Linear and Notion fields, Polaris), writes a short rationale in this row, and rebuilds InlineEdit: read state → edit state; actions **under** the control, small (`sm`), Save then Cancel, left-aligned, the same on desktop and phone; Enter saves and Escape cancels (per control: Textarea keeps Enter for new lines); pending and error states; no layout jump between read and edit. The docs page shows every control kind it hosts, **including a switch** (where an immediate toggle may need no Save at all; the rationale decides) | **built**. Rationale (after Atlassian's inline edit, GitHub's in-place title and comment edits, Linear and Notion properties, and Polaris, which has no inline edit and sends edits to a page, a modal or a save bar): (1) **Two states in one box.** Read is the label, then the value as one button (a pencil at its end, always visible since touch has no hover; its name is the value, then "Edit <label>"). Edit puts the control in exactly that box: the read row has the control's height, 1px border, 12px padding and 500-weight text, so the value doesn't move when it becomes editable (Atlassian's trick). (2) **Actions under the control, in the flow,** `sm`, Save then Cancel, left-aligned, the same on desktop and phone. Under, not beside, so a narrow column never squeezes the field; in the flow, not floating as Atlassian's do, so they never cover the next field and the error has room. Content below moves down by one row once; that's the only shift. (3) **Keys:** Enter saves (input, a closed select with a value, a typed field with no error); Textarea keeps Enter for new lines and saves on Ctrl/⌘+Enter (GitHub's comment key); Escape cancels and puts the saved value back; after either, focus returns to the read button. Blur never saves: with explicit buttons, a click on Save must not race a blur, and half-typed text is never committed for the person. (4) **Pending/error/success in place:** onSave may return `{ error }` or a promise; pending says "Saving…" with both actions aria-disabled (focus stays put) and the control read-only, so a second save can't happen; an error shows under the control, which turns aria-invalid and is described by it, keeps the typed value and takes focus back; success returns to read with the new value and a "Saved" check for 2.5s, announced politely. No banner (company rule). (5) **Booleans:** a switch means "this takes effect now" (Apple HIG, NN/g, Linear, Notion, GitHub settings), so `control="switch"` has no Save, no Cancel and no read/edit split: the flip shows at once and calls onSave(boolean); while pending a spinner sits beside it and further flips wait; a failure flips it back and says why under it. The switch is its own undo, so no undo toast (it would be a banner). A boolean that must wait for a Save is a checkbox in a form, not an InlineEdit. Built: `forms/inline-edit.tsx` rebuilt to that (props a union on `control`; `formatValue` for the read state, so a typed field shows a formatted phone, a masked SSN or password, never the raw value; `editing`/`onEditingChange` for a caller with its own read state; `defaultEditing`; copy in `formMessages.inlineEdit`, labels Save and Cancel, the old "Never mind" retired). New **Switch** (`components/inputs/switch.tsx`, 40 × 22 track, 20px thumb, off in the muted ink at 3:1) over a new `base/switch.tsx` written from the shadcn registry's JSON (the CLI wasn't run with the servers up; `ui:diff-base switch` matches). FactField drives InlineEdit controlled (`editing`, `hideLabel`) and now returns focus to its own Edit/Change/Add. The docs page shows every control it hosts (Every control: input, select, textarea, DateField, PhoneField, CurrencyField, switch) plus read filled/empty, each control editing, pending, error, long value (read and editing), narrow (320px), and plays for Enter, Escape, Select keys, Textarea keys and the switch's save, pending and error.
