# API contracts the web side relies on

Moved from `CLAUDE.md` (R17-14). The full list of what the API owes is `API-NEEDS.md` at the spike root.


The API isn't in this spike. **The full list is [`API-NEEDS.md`](../../API-NEEDS.md)** at the spike root (R13-01): one row per API change the UI work has found, with the shape the UI expects and the file that consumes it, so the API side can do them together. The contracts below are the ones already written into the web code (REVIEW-2 group E):

- **Rich text (R2-37).** The web stores and sends the editor's JSON document, never HTML. The schema is `src/schemas/rich-text-value.schema.json` (JSON Schema 2020-12, exported as `@paige/ui/schemas/rich-text-value.schema.json`), matching `RichTextValue` in `components/inputs/rich-text.tsx`; change the two together. The API owes: (1) validate every rich value on write against that schema (reject, 400 with a field error, on unknown nodes, marks, attributes or link schemes; cap size and depth); (2) a server renderer from the same JSON: HTML for SendGrid (escape all text, links only http(s)/mailto/tel with `rel="noopener noreferrer nofollow"`) and QuestPDF spans for PDFs (bold, italic, lists, links as text plus URL); (3) an ADR that records the schema and supersedes ADR 0038's TinyMCE and sanitized-HTML half. ADR 0038's plain-vs-rich rule stands: rich only for messages and memories.
- **Error responses (R8-02, GAPS #103).** What the API returns today (`src/api/modules/Paige.AspNetCore/Errors`, ErrorBoundaryMiddleware): every failure is `{ status, correlationId, errors: [{ code, message, type, rule?, data? }] }` (camelCase, `type` a camelCase enum: `input`, `business`, `authentication`, `security`, `notFound`, `rateLimited`, `payloadTooLarge`). It is not RFC 7807 problem details and there is no `errors` map. Status: 400 input, 409 business (a missing subject is 409 `*_not_found`), 401, 403, 413, 429, 500 (`system.unhandled`, `system.dispatch`); a body that didn't bind is 400 `request.binding`. Input-attribute codes are `<member>.<validator>` (`legalName.notNullOrWhiteSpace`, `email.emailAddress`; a wire refusal names the JSON path, `address.zip.invalid`); rule and handler codes are snake_case (`email_in_use`). `forms/api-errors.ts` maps it (tests: `api-errors.test.ts`). The contract the API keeps for forms: (1) a field error is an `input` error whose code starts with the request member's camelCase path, and the web names its Field after that member; (2) a rule about one field either uses that form (`email.inUse`) or the form lists it in `fields`; (3) `message` is written for the person (never exception or binder text), and Product may replace it per code in `messages`; (4) 401/403/429/5xx bodies are never shown.
- **Pipeline step inputs and outputs (R10-11, GAPS #112).** PipelineGraph's details panel shows a step's `inputs` and `outputs` (`{ name, value }[]`, value a string, number, boolean or null) when the run detail carries them; the pipeline run endpoint (RunPipeline.md, PipelineRunDetail) has none per step today, so they're absent, never an empty section. The API owes: optional `inputs`/`outputs` per step in the run detail (or a rows-read / rows-written summary), named for operators, never raw payloads or PII.
- **Setup beat saves (R2-38).** Form owns the submit (R7-03) and FlowFooter's submit mode shows it. About you submits through Form now (its fields are checked, ErrorSummary on a problem) but saves nothing: onSubmit only moves on, as the link did, until the API has a save endpoint per beat (About you, roles, …) returning the error shape above. Roles stays in link mode. Each beat's onSubmit then calls its endpoint and returns `formResultFromResponse(res)` on a failure.
