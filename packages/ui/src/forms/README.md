# Forms and Fields

Moved from `packages/ui/CLAUDE.md` (R17-14): how forms, fields and their value shapes work. The package rules and layers are in `../../CLAUDE.md`; the server's error shape is in `../../CONTRACTS.md`.

## Forms (R7-03)

Four levels (ORGANIZATION.md §4): **controls** (Components › Inputs: Input, Textarea, Select, RadioGroup, Switch; no label, no value semantics), **fields** (Forms › Fields: value-shaped, parse, format, validate, report their own error), **form patterns** (Forms: Form, Field, FormSection, FormFooter, ErrorSummary, InlineEdit; ChoiceCard is Vault's, R11-05; FlowFooter is Setup's since 2026-10-30, it was here by what it imports) and **domain forms** (one feature's capture form, bound to its API contract: `apps/web/features/<feature>/forms/<thing>-form.tsx`; promote to `src/vault/forms/` only when a second feature needs it and it carries no API types). The route composes template + form: the page owns navigation, the form owns data (`apps/web/features/setup/about-you-beat.tsx` + `forms/about-you-form.tsx` is the first one). Names: **Field** is the frame; ***Field** (DateField, PhoneField…) is a value-shaped control; FactField (Vault) is a domain row.

- **Field wires its control.** Field owns the control's id, the label's id and the ids of its FieldDescription and FieldError, and shares them through context: Input, Textarea, Select and every typed field take `id`, `aria-describedby` (only the parts on screen) and `aria-invalid` from it, and FieldLabel's `htmlFor` points at the id. No hand-written `id`, `htmlFor` or `aria-describedby` in the app. A control's own props still win, **except `id`** (R8-05): inside a Field the control's own `id` is ignored, with a dev-only console warning, so the label link can't break; if something outside needs the id, set it on Field (`<Field id=…>`). `check:layers` (FIELDID) fails on an `id=` written on a control inside a `<Field>`, in the package (stories too) and the app.
- **Linked on the first paint** (R8-04). The ids derive from the Field's `useId`, and Field finds its FieldDescription and FieldError among its children while rendering (through plain elements and fragments), so the server HTML already carries `aria-describedby` (`/setup/about-you` shows it). A part wrapped in another component joins once it mounts. A FieldError counts only while it has something to say.
- **Value shapes are the contract** (the Fields table below): ISO date strings, E.164, integer cents, ZIP strings; never `Date`, never a float. Name them with the types in `forms/values.ts` (`IsoDate`, `E164`, `PostalCode`, `SsnDigits`, `Cents`).
- **Complete or empty; empty is not an error.** Required-ness is the form's (`validate`, or the submit's `disabled`).
- **One copy map** (R5-04): `forms/messages.ts` holds every word the fields (`fieldMessages`) and the form (`formMessages`: ErrorSummary's heading, the generic failure, "Saving…") say. Product's copy lands there in one edit; the wording now is the spike's own (GAPS #94).
- **Errors by Field `name`.** A typed field reports its own message to its Field (after blur or Enter) as well as to `onValidate`; inside a Form a named Field also shows the form's error for its name: `validate`'s (after the first submit, updated as values change) or the server's (`errors`, or the `{ errors, error }` onSubmit returns, kept until the next submit). `<FieldError />` with no children shows whichever stands. A form-level failure shows in ErrorSummary only.
- **Unsaved changes warn** (R8-01). Form is dirty while its values differ (structurally) from where they started: `initialValues`, else the values on the first render, then the values last saved. While dirty and not submitting, a tab close or reload gets the browser's `beforeunload` prompt, a click on a link to another page (Next `<Link>`, FlowFooter's Back, a plain `<a>`) asks `formMessages.unsaved` and stays on No, and so does the browser's Back (R9-02): while dirty the form keeps a guard history entry (this page's URL and state plus a flag) on top, so Back lands on this same page first (the router restores it in place) and asks; No puts the guard back, Yes goes back for real. A submit takes the guard entry off before onSubmit runs (a failed submit that leaves the form dirty puts it back), and so does unmounting on the page (R10-13, GAPS #114), so after a save that navigates Back passes the page in one press. Forward past the page is dropped once it's dirty. Code that navigates by itself asks `handle.confirmLeave()` first; `handle.dirty` is there for a screen that wants it. `warnUnsaved={false}` for a form that saves as you go.
- **Server errors through `forms/api-errors.ts`** (R8-02). A domain form's onSubmit returns `formResultFromResponse(res, options)` (or `formResultFromApi(status, body, options)`) on a failed response: member-path codes land on the Field of that name, `fields` assigns a snake_case code to a Field, `messages` puts Product's copy over the API's, anything else is the form-level error; 401/403/429/5xx use our copy. The wire shape and the contract are under **API contracts** below.
- **Submit state comes from Form**, never the screen: idle → pending (the submit is disabled and says "Saving…"; a second submit does nothing) → success (onSubmit navigates or shows the result in place; no success banner) or failure (ErrorSummary at the top takes focus and is announced, lists each problem with a link that focuses its field — one problem reads as a sentence under "Check this and try again", two or more as bullets under "Check these…", and a form names its own failure with `summaryTitle` ("Couldn’t sign in"), R18-24; every input is kept; the submit is ready to retry). onSubmit throwing shows the generic failure, never the exception text. Values are the caller's (typed state handed to `onSubmit(values)` and `validate(values)`); the form-state library is Engineering's call when the first save endpoint lands (R2-38), and Form's API doesn't depend on it.
- **Footers.** FormFooter (cancel + submit) inside a plain Form reads pending and disabled from it; `fill` (REVIEW-18 R18-08) makes the actions fill the width with no rule above, for a form that is a card's whole body (the auth pages). FlowFooter (`setup/flow-footer.tsx`, Setup's since 2026-10-30) stays the setup steps' footer (Back, a note, Skip, the primary action; decided against folding it into FormFooter): inside a Form it reads the same state; when the template puts it outside the `<form>` (SetupBeat's `footer`), call `useForm(...)` in the route, pass the handle to `<Form form={…}>` and `handle.submitProps` to FlowFooter's `submit`. Both use one submit button (`forms/internal/submit-button.tsx`).
- **Sections with FormSection** (GAPS #50), never a hand-built eyebrow + Separator row. Related fields under one legend are a FieldSet. A label beside a radio or checkbox is a Field.

## Fields (R4-12, George 2026-10-19)

The typed field controls: DateField, DateOfBirthField, PhoneField, PostalCodeField, SsnField, CurrencyField, PasswordField (R5-02), AddressField (George 2026-10-28) (Forms › Fields, `src/forms/fields`; their helpers in `src/forms/internal`). Logic lives in `src/lib` as pure, tested functions (`dates.ts`, `mask.ts`; `npm test`); the components are thin.

| Field | Value | Accepts |
|---|---|---|
| DateField | ISO `"YYYY-MM-DD"` or `""` | `3/4/26`, `03042026`, `March 4 2026`, `4 Mar 2026`, `2026-03-04`, in en-US order (R5-01); a calendar (fine pointer) or the native date input (touch) |
| DateRangeField | `{ from, to }`, each ISO `"YYYY-MM-DD"` or `""` (an open side) | presets (Last 7 / 30 / 90 days, This year: fixed dates for today) or two DateFields, From and To, each the other's bound; native date inputs on touch (R3-16); `lib/date-range.ts` (tested) |
| DateOfBirthField | ISO `"YYYY-MM-DD"` or `""` | the same, typed only (no calendar); two-digit years in the past; future and `minAge`/`maxAge` rejected |
| PhoneField | E.164 `"+15551234567"` or `""` | any US phone text: `+1 (555) 123-4567`, `5551234567`, `555.123.4567` |
| PostalCodeField | `"12345"`, `"12345-6789"` or `""` | ZIP or ZIP+4 in any shape |
| SsnField | nine digits or `""` | digits in any shape; shows `•••-••-6789` |
| CurrencyField | integer minor units (cents) or `null` | `1234.5`, `$1,234.50`; minus only with `allowNegative` |
| PasswordField | the text as typed | anything; `autoComplete` is `"current-password"` (default) or `"new-password"`; no rules of its own — `PasswordStrength` (R20-20) sits under it when the password is new: the API's rules (length, a digit, a symbol), a four-step bar and one `aria-live` verdict |
| AddressField | `{ text, address }`: the box's text, and a `PostalAddress` (`lib/postal-address.ts`, every key present, `""` when not set): by default the pick's parts while the box still says it, else `null`; with `validate`, always the street and parts (maybe partial, so the caller checks it's whole) | any text, with suggestions from `source` (a list, or a lookup: Photon in the app). By default (setup) the text is the answer: a full address, part of one, or a city; a pick puts the whole address in the box. `validate` (after sign-in): the box is the street with the apt beside it (80/20, the apt's label lifted onto the street label's line), a pick fills the rest, and when the street doesn't resolve (nothing found, the lookup failed, left without a pick) city, state and ZIP appear, each its own Field. US only; no `name` hidden input yet |

- **en-US only** (R5-01, George 2026-10-19). en-US is the only locale built and tested. The plumbing stays: every date and money field takes `locale`, every format comes from `Intl`, so nothing has to be torn out later, but the default is `"en-US"` everywhere (`DEFAULT_LOCALE` in `lib/locale.ts`, used by the fields and by `lib/dates.ts`/`lib/mask.ts`), never the browser's, which also keeps the server and client renders the same. Another locale is untested and partly wrong (GAPS #95, #96, deferred with R5-05). `lib/*.ts` import each other with a `.ts` extension (for `node --test`), so `apps/web`'s tsconfig has `allowImportingTsExtensions`.
- **Never a `Date` object across an API.** Dates are ISO strings; `Date` appears only inside `lib/dates.ts` and the calendar adapter. Money is an integer in minor units, never a float.
- **The value is complete or empty.** A half-typed entry stays in the input (never cleared) but the value is `""` (or `null`) until it means something whole and valid.
- **Every word a field says is in `forms/messages.ts`** (R5-04): errors, screen-reader format hints, in-field action labels, one map per field. Product's copy lands there in one edit; the wording now is the spike's own (GAPS #94). A caller can still override a field's errors per use (`messages` / `invalidMessage`).
- **Errors come from the field.** Each field reports its own message on blur or Enter (and updates it on every change once shown), to its Field (which marks itself invalid and shows it in `<FieldError />`, R7-03) and to `onValidate` for callers outside a Field. Empty is not an error: required-ness is the caller's.
- **The caret never jumps.** Dates are never reformatted while typing (only on blur). Masks place the caret by counting digits (`lib/mask.ts applyEdit`), and Backspace just after a separator deletes the digit before it.
- **SSN is never logged**, nor put in telemetry, URLs or error reports. It is masked by default, shown in full only while its Show SSN toggle is on (until focus leaves the field) or while focused with `revealOnFocus`, opts out of autofill and password managers, and only reaches the DOM in full through `name`'s hidden input, which is for a form that really posts it.
- **`name`** adds a hidden input carrying the value (not the display text). PasswordField puts `name` on its own input instead, so password managers see the real field.
- **In-field icons are FieldActions** (R5-03): a real `<button type="button">` with an `aria-label`, a 16px icon in a 24px target, no chrome, muted until hovered; it sits in the field's `InputGroup` trailing addon (U-02), which keeps the text clear of it. Fields with one: **DateField** (the calendar, "Choose date"), **PasswordField** (show/hide, "Show password", `aria-pressed`), **SsnField** (show/hide, "Show SSN", `aria-pressed`; masks again when focus leaves the field; `reveal={false}` drops it). A toggle keeps one label in both states and `aria-pressed` says which (R6-01, WAI-ARIA's toggle-button pattern); a label that changes with the state goes without `aria-pressed`, never both. A reveal click keeps focus, caret and selection in the input (`useKeptSelection` in `forms/internal/field-support.tsx`, which forces a layout first: Chrome resets the caret after a real click on an input whose `type` changed, GAPS #99). A play can't send a real click, so that stays a by-hand check (spike README § By-hand checks). Phone, ZIP, date of birth and currency have none.
- **Passwords are never logged** either: same rule as SSN.
- **InlineEdit** hosts any of them with `control="field"` and `renderControl={(c) => <DateField {...c} />}` (plus `formatValue` for the read state: a formatted phone, a masked SSN or password, never the raw value); Save and Enter do nothing while the field reports an error.
- **InlineEdit's experience** (R11-04, rationale in REVIEW-11): a read state (label, then the value as one button with a pencil) and an edit state in the same box (the read row has the control's height, border width, padding and text, so the value doesn't move; both boxes are pulled out by that padding, R12-04, so the value lines up with the label and the hover box hangs just outside the column); actions under the control, `sm`, Save then Cancel, left-aligned, the same at every width. Enter saves (Textarea: Ctrl/⌘+Enter), Escape cancels and restores, focus returns to the read button, blur never saves. onSave may return `{ error }` or a promise: pending ("Saving…", aria-disabled actions, read-only control), error under the control with the input kept, success shown in place ("Saved", announced; no banner). `control="switch"` saves on the flip, no Save or Cancel, flips back on a failure. FactField's value *is* InlineEdit's read state (R12-06, one read state for one value): FactField adds only the eyebrow and badge above and the source line and its actions (Confirm, Add, the decline) under it; it drives `editing`/`onEditingChange` so Add opens the same editor, and an answer without a value shows as `emptyText`. Copy in `formMessages.inlineEdit`.
- **Play functions** edit text with `typeKeys`/`pasteText`/`clearText`/`enter`/`leave` from `src/stories/typing.ts` (R5-08), never `userEvent.type`, which loses track of an input that reformats as you type (GAPS #97); `userEvent` stays for clicks and non-editing keys. `src/stories/field-frame.tsx` is only the Field wrapper. **Focus** (R12-03, GAPS #122): a play moves focus with `enter(el)` / `leave(el)`, never `el.focus()`, because without system focus (a background tab, the preview pane) the browser fires no focus events and anything that opens on focus stays shut; `enter`/`leave` send them by hand in that case. Assert on state (a role present, `aria-expanded`, `toHaveFocus`), never on a focus event having fired. Anything that opens on focus also opens on a click or on input. The few plays that still need a foreground window are listed in the spike README's by-hand checks.
