# @paige/ui — module guide

The Paige web component library: one Tailwind v4 theme (`src/theme.css`), upstream shadcn components as the base, a Paige layer over them, forms, patterns, the app shell, the Vault's own pieces, and the templates every screen sits in. `apps/web` (Next 16) consumes it through `transpilePackages`; Storybook 10 (React + Vite) on http://localhost:6106 is its browser. Spike status: built for the test pass (`spikes/paige-ui-test-pass`, REVIEW-1 / GAPS.md).

Read this first. **Where the rest lives** (R17-14): the catalog ("which component do I use for…?") is `CATALOG.md` (generated); the admin pieces' decisions are `src/admin/README.md`; forms, fields and value shapes are `src/forms/README.md`; the API contracts are `CONTRACTS.md`; why the folders are what they are is `ORGANIZATION.md`; the libraries, one per job, and what each keeps out is `STACK.md` (`check:deps` holds it). The quality pass of 2026-10-29 is at the spike root: `AUDIT.md` (measured state, A-nn), `ARCHETYPES.md` (archetypes, the axis vocabulary, renames, D-nn), `TOKENS.md` (token inventory, the geometry tier, the surface model, T-nn) and `REUSE.md` (shadcn bases and who inherits them, components drawing outside their area, U-nn); `npm run audit` regenerates their measured sections.

## Layers and the import rule

One folder per layer (R7-01…05, `REVIEW-7.md`; the reasoning is `ORGANIZATION.md`). The folder is also the Storybook section (`.storybook/main.ts` maps each folder with a `titlePrefix`; story files have no `title:`), so a file's place in the tree is its place in the sidebar, subfolders included (`src/components/inputs/select.stories.tsx` → Components › Inputs › Select).

TabsLine (Navigation, R21-03) is underline tabs for views of one page, TabsPill's sibling with the same list/trigger shape (`TabsLineList` + `tabsLineTriggerVariants()`; links with `aria-current` or Radix Tabs' list); it draws no rule of its own and sits on its holder's (AdminPage's `tabs` slot). Which group: a toggle group holds a state (`aria-checked` / `aria-pressed`), a ButtonGroup is actions side by side — DagFrame's Graph/List is the toggle group, its zoom column the button group (R20-13). Small parts (R20, 2026-10-31): Breadcrumb (Navigation, over the `breadcrumb` base, R20-15) is the trail to the current page as data (`items`, the last one is the page, `aria-current="page"`): muted `focus-ring` links, a muted chevron, `linkAs` for the router link; a trail longer than `maxItems` (default 3, the caller's for a narrow container; `Infinity` never collapses) keeps its first level and the last `maxItems − 1` and puts the rest behind an ellipsis button that opens a DropdownMenu of links, so no level is unreachable; no breakpoint classes. HoverCard (Overlays, over the `hover-card` base, R20-16) is a small read-only panel opened by hover or focus (`openDelay` 300, `closeDelay` 150) on the shared popover surface; supplementary by rule: it does not open on touch, closes when the pointer leaves and holds no controls, so the same detail must be reachable another way and its trigger is always a link or button. Timeline (Display, an Item, R20-18) is a vertical rail of events (ReUI's `timeline`, MIT, as `<ol>`/`<li>`; the group shape re-derived from Rocket's description, D-01): `items: TimelineEntry[]` (`title`, `description`, `time`, `status`, `icon`, `children`, `defaultOpen`) or the parts (`TimelineItem`, `TimelineIndicator`, `TimelineContent`, `TimelineTitle`, `TimelineDescription`, `TimelineTime`, `TimelineSeparator`, `TimelineGroup`); the dot is StatusMark when there is a `status` (`working` is the current step, `aria-current="step"`), else the icon, else a Dot; `rail` start · end. An entry with `children` is a group: its title toggles our Collapsible (`aria-expanded`, `aria-controls`, CSS fold, no `motion`), controlled by `open` (id → open) with `onOpenChange(id, open)` or uncontrolled with `defaultOpen`; `collapsible={false}` draws every group open with no toggle. Sortable (Inputs, a Control, R20-19, from ReUI over `@dnd-kit`) is the list, the handle and the keyboard reorder; each row's content is the caller's (an Item, a chip). Controlled: `items` is the order of ids, `onReorder(next)` gets the whole new order after a drop; `SortableItem` children in that order, or `renderItem(id)`. `handle` is true (a `SortableHandle`, an IconButton named "Drag {name} to reorder" from `itemLabel`), false (the whole row drags and is the focus target; a touch screen scrolls there, so use the handle on a phone) or "custom" (the caller places `SortableHandle`). Space picks up, the arrows move, Space drops, Escape cancels; a live region says where the item is in our words. A dragged item is lifted (`shadow-lift`, `z-raised`, `data-dragging`); a disabled item stays put. No overlay clone: one list needs none. Formatted (Display, a Text, R20-21) is a count, amount, percent, date, date-time, duration or file size written the Paige way, inline (`<time dateTime>` for the times, `tabular-nums` for numbers, a `title` with the full value when shortened, "—" and a spoken "No value" for nothing — never 0); the words come from `lib/format-kind.ts`, which the DataTable column `type` will share; `tone` strong · muted · attention (R21-10, the attention ink for a value the page judges needs a look). Inline data marks (R21, 2026-10-31; Display, Chart archetype, HTML with the data value as one CSS variable): MeterBar (R21-07) is one quantity against its whole (`role="meter"`, "84 of 101", `showValue` prints the count); RangeBar (R21-08) is a spread on a shared `domain` — the box (low–high), the median tick, an optional whisker — named by its `summary`; Legend (R21-09) is the row of swatches (`block` · `line` · `dot`) and labels that explains them, with values under a ShareBar. All three name their colours from one list (`components/internal/data-color.ts`: brand · brand-subtle · brand-ink · attention · neutral · chart-1…5), so a bar and its legend can't disagree. DataTable `currentRowId` (R21-11) holds the hover wash on the row whose detail is showing (`aria-current`). ShareBar (Display, R21-13) is how one whole splits: one stacked 14px bar and its Legend (dots, counts), the legend being what assistive tech reads. NavList (Navigation, an Item, R21-12) is a vertical in-page nav of a page's views: label, trailing count, a named attention Dot; buttons (`onSelect`, `aria-current="true"`) or links (`href`, `aria-current="page"`); the current one in the sidebar's active roles with a 3px brand bar; `framed` for the white card. An `internal/` folder (`components/internal`, `forms/internal`, `shell/internal`) holds helpers for its own layer and the ones above: never exported, no story, not in the catalog.

**Layer order** (R7-02, R8-06). Each folder imports only its own layer or a lower one: `lib → icons|schemas → base → primitives → components → charts → forms → patterns → shell → vault|admin|setup|auth → templates`. Peers in one step (vault, admin, setup and auth, the four product areas) don't import each other; shell is shared chrome under all of them. Only `src/components`, `src/charts` (the chart base) and `src/forms` (for the bases it wraps: Field, Calendar, Popover) import `src/base`. No runtime import cycle anywhere (`import type` doesn't count). Stories, `src/stories`, `src/foundations`, `src/docs` and `src/fixtures` may import any layer, never Base unless they're Base stories. The order is one declared list, `TIERS` in `scripts/check-layers.mjs`; `npm run check:layers` fails on an upward or sideways import, a cycle, or a folder that isn't in the list. A control reads its Field through `components/internal/field-context.tsx`, which is why that context lives below Forms.

**`AreaId` lives in `icons/area-glyphs.tsx`** (R8-03, GAPS #104). It is a domain type, but Badge (Components) takes an `area` prop and Vault, Shell and Templates all use it, so it sits in the lowest tier every user can import. `vault/areas.ts` (ORGANIZATION.md rank 5) would make Badge import upward; `lib/` would split the ids from the glyphs keyed by them. It stays until Badge's `area` prop goes (a tone set by `data-area` only), and then moves to `vault/`.

**Public surface** (R7-05). `package.json` `exports` names every entry point, no wildcards: the key is the file's path under `src/` without the extension (`@paige/ui/forms/fields/date-field` → `src/forms/fields/date-field.tsx`), `.ts` and `.tsx` alike. `internal/`, `base/`, stories, tests and the story-only folders are never entries. The app imports only entry points; inside the package, imports stay relative and point at the file (no barrels). `npm run check:exports` fails on a missing target, a private entry, a key that isn't its path, a public file with no entry, and an app import that isn't an entry; after a move, `node scripts/check-exports.mjs --write` regenerates the map (review the diff). The app's TypeScript resolves through the same map, so a non-entry import also fails `npm run typecheck`.

**Server-safe helpers.** Callable `cva` helpers and style constants (`cardVariants`, `tabs-pill-styles.ts`, `internal/control.ts`, `internal/popover-surface.ts`) stay in files without `"use client"` so server components can call them; `check:layers` fails when a `"use client"` file outside `src/base` exports a `cva` helper (R2-33).

**Radix through the base** (U-12). Outside `src/base`, a component takes every Radix part the base re-exports (Root, Trigger, Portal, Overlay, Title, Close…) from the base, so an upstream change to them is inherited. It imports `radix-ui` directly only for a part the base cannot give — Dialog's and AlertDialog's `Content` (the base's carries its own overlay), AlertDialog's `Cancel` (the base's applies `buttonVariants`), DropdownMenu's `ItemIndicator` (not re-exported) — and each is listed in `PRIMITIVE_OK` in `scripts/check-layers.mjs` with its reason; anything else is a `PRIMITIVE` finding. A base earns its place by an importer: `audit:reuse` reports one with none (an upstream internal such as `sheet` under `sidebar` is kept with its importer).

## Rules

- **Tokens only.** Colours, spacing, radii, shadows and type come from `theme.css` utilities. No arbitrary values (`p-[13px]`, `text-[#…]`), no `!important`, no inline `style={{}}`.
- **Hover is relative** (R4-01). A non-primary interactive surface hovers with `hover:layer-hover` and presses with `active:layer-press` (the overlay over whatever it already is), never a fixed hover colour such as `hover:bg-muted`, which vanishes on a muted surface. A trigger whose panel is open keeps `layer-press` (`aria-expanded:` / `data-[state=open]:`). Tailwind's `hover:` only applies under `@media (hover: hover)`.
- **A new utility gets a merge entry** (R2-21). Every `@utility` in `theme.css`, and any token class tailwind-merge can't infer (`tracking-display`, `shadow-lift`), is registered in `extendTailwindMerge` (`src/lib/utils.ts`) with a case in `src/lib/utils.test.ts`. Otherwise `cn()` keeps or drops a conflicting class by guesswork.
- **Body text is 400** (R2-17). Secondary text the prototype draws at 500 (ledes, a tile's line, panel and row descriptions, source lines, field hints, message bodies) says `font-medium` where it's drawn; nothing inherits 500. Form values are 500 and placeholders 400 (R3-01): `controlValue` in `components/internal/control.ts`.
- **Brand fonts come from the host** (R2-20). The package ships no font files. The host loads the fonts and defines `--font-brand-sans` and `--font-brand-display` on an ancestor (apps/web: `next/font` in `app/layout.tsx`; Storybook: `.storybook/fonts.css`). `font-sans`/`font-display` fall back to named and generic faces without them.
- **Upstream shadow names are aliases** (R2-18): `shadow-xs`/`shadow-sm` = card, `shadow-md`/`shadow-lg` = pop, so bases cast real shadows. A Paige wrapper whose surface is flat in the prototype says `shadow-none` (Card when not interactive, Button `secondary`).
- **No hex outside `theme.css`.** It is the only file that holds raw colour, shadow or size values.
- **`cva` only in this package.** The app composes; it never defines variants.
- **Every component file declares its archetype** (ARCHETYPES.md §2, §7). The header's first line is `@archetype Action` (one of Action · Control · Surface · Mark · Media · Text · Overlay · Frame · Item · Chart · Composite); Storybook reads it into an `archetype-action` tag on the file's stories (`.storybook/main.ts`), and `AUDIT.md`'s scorecard has the column. The archetype fixes which axes the part may expose and their words: `src/lib/vocabulary.ts` holds the sets (`Tone`, `ActionEmphasis`, `Fill`, `Density`, the size scales…); a component narrows one with `Extract<…>`, never writes an inline union on an axis name or a retired word (`variant`, `ghost`, `appearance`). `npm run check:vocab` reports the gaps; it warns until George's pass on the words (ARCHETYPES.md §8 step 1) and then fails at level 2+ (`--strict`). The 74 warnings it starts with are ARCHETYPES.md §4's "After" column, one per line.
- **Page layout belongs to templates.** The page frame, gutter and page widths (`page-frame`, `px-gutter`, `max-w-page|focused|wide`) are used only in `src/templates` and `src/primitives` (and AppHeader's row).
- **Header actions are global (R1-28).** AppHeader holds only what applies on every page (search, notifications, account, the Mode switch). Actions for the page you are on (add, edit, export, filter) go in that page's `PageHeader` `actions`, never in the header.
- **Header popovers (R11-08…R11-11).** Actions sit 16px apart; the avatar is md 34 (a photo wears Avatar's own border, R13-13). Anything a header action opens is a real popover (Components › Overlays › Popover, or DropdownMenu): a click outside or Escape closes it, and AppHeader's `PopoverGroup` (also around AdminPage's global actions) keeps one open at a time through `usePopoverGroup(id)` (`components/internal/popover-group.tsx`): HeaderSearch's results, NotificationBell's `panel`, and AccountMenu through DropdownMenu's `group` prop (AccountMenu stays a server component: a client component can't take the app's `linkAs`, a function, from the server). HeaderSearch is the expanding search (icon → field, `/` focuses it, grouped results, combobox keys); the caller passes `groups` for its `query`. Never an absolutely positioned div that stays open.
- **Arrange with primitives**, not ad-hoc flex classes: Stack (vertical), Inline (horizontal, wraps), Grid (columns), Split (content + actions that drop under it). Flex (R4-10) is the general row/column that Stack and Inline are presets of; use it only for a layout none of the named ones covers.
- **Spacing steps** (R2-40). Padding, margin and gap use whole steps of the 4px grid in primitives, templates and the app; components, forms, patterns, shell and vault may also use half steps (2px) for optical alignment. Nothing finer. `check:tokens` enforces it.
- **One speed, three stacking steps** (T-12). Every `transition-*` runs at the theme's `--default-transition-duration` (200ms); a component writes `duration-*` only for a deliberate departure, with the reason beside it. The looping animations are the theme's: `progress-pulse` and, since R19, `shimmer` (the highlight sweeping an Attachment's name while its file is in flight; the `attachment` base expects it, `theme.css` draws it, and it stops under reduced motion). Stacking is `z-raised` (above siblings inside one surface), `z-sticky` (chrome the page scrolls under) or `z-overlay` (a layer over the page); no bare `z-n` in component code.
- **State and on-tone ink are tokens** (T-07, T-08, T-09). Disabled is `opacity-disabled` (.5), a quiet icon at rest is `opacity-quiet` (.75, S-35's 3:1 floor), a pushed-back series is `opacity-dim` (.4); no bare `opacity-n`. Ink on a tone fill is `text-on-tone`, never `text-white`. A derived alpha has a name in `theme.css` (`bg-overlay-hover`, `bg-overlay-scrim`, `ring-focus-halo`, `hover:bg-destructive-hover`), never `bg-overlay/8`, `ring-ring/50`, `bg-destructive/90` in a component. `check:tokens` (`state-ink-alpha`) enforces it; the contrast test (`scripts/theme-contrast.test.mjs`) keeps the numbers honest.
- **Controls and glyphs are on a scale** (T-01, T-02). A control's height is `h-control-sm` (36: Button sm, the icon button `size-control-sm`, a toolbar's field, a pill), `h-control` (44: Input, Select, Button md, an InlineEdit row), `h-control-lg` (48) or `min-h-textarea` (72); `controlHeight` in `components/internal/control.ts` is the typed-control one. A toolbar's floor is the small control it holds (`min-h-control-sm`); a field's inset for a leading icon or trailing control is `pl-control-sm` / `pr-control-sm`. A glyph is `size-icon-xs` (12), `size-icon-sm` (14), `size-icon` (16, the default in a button, menu item or row), `size-icon-lg` (20) or `size-icon-xl` (24), on the svg or through `[&_svg]:` / `[&>svg]:`. No bare `h-11`, `size-9`, `pl-9`, `[&_svg]:size-4`, `<CheckIcon className="size-4" />` in component code; `check:tokens` (`geometry`) enforces it. Marks (Dot) and media (Avatar, AreaIcon, wells, the 40px media column) wait for their own scales (T-03). Radius: `rounded-xs` (4px, fixed) is the step for a control under 24px (the Checkbox box); `sm` 8 · `md` 10 · `lg` 12 · `xl` 16 follow `--radius`. `rounded-sm` on a box under 24px draws a circle (R20-01: the Checkbox was one; AreaIcon `sm` at 20px still is, GAPS #152). FileIcon is drawn at 18 / 24 / 32 / 40; 24 is `size-icon-xl`, the others have no token until the media scale (T-03) names them (GAPS #153).
- **A thing you can reorder is a Sortable** (R20-19). `components/inputs/sortable` for any list, chip row or card set whose order the person sets; never wire `@dnd-kit` in a screen. The part owns the sensors (pointer with a 4px start, keyboard with `sortableKeyboardCoordinates`), the announcements and the handle; the caller owns the rows and stores the order from `onReorder`. Name each item (`itemLabel`) when ids aren't words, so the handle and the live region say who moved. Row and column reordering in the data grid (R20-23) reuses it rather than a second drag layer.
- **A hover card is never the only way** (R20-16). HoverCard opens on hover and focus, never on touch, and holds no controls; whatever it shows must be reachable on a page too. Its trigger is a link or a button with a name.
- **Actions carry an icon** (R20-04, George 2026-10-31: *"all context menus should use icons. anything that is an action. that isn't the case for select menus"*). A menu entry that does something or goes somewhere has an icon: `ListAction` (`components/internal/list-action.tsx`, the vocabulary of RowActions, BulkActionBar and Item) requires `icon` on `action`, `link`, `destructive` and `menu` and on a menu's items, so a missing one fails `tsc`. A pick-list (choose a value: Personal / Family / Household; a sort order) is exempt: `Menu`'s raw `item` keeps `icon?`.
- **Overlays, charts and bars are on a scale too** (T-04, T-05, T-06). What floats is `min-w-menu` (192, a submenu), `min-w-menu-wide` (224, a menu: `popoverContent`), `w-popover` / `w-popover-wide` (320 / 384: Popover, HeaderSearch's results, DagFrame's details), `max-w-dialog-sm` / `dialog` / `dialog-lg` (448 / 672 / 896: Dialog, ConfirmDialog; FiltersPopover is `w-dialog-sm`). A pill with a leading avatar, icon or glyph has the same space above, below and before it; the text side is wider (`pr-3.5`). `PersonPicker`'s `PILL` + `PILL_MEDIA` (avatar: `py-1 pl-1.5`, so 6 / 6 / 7 with the 1px border) and `PILL_ICON` (glyph: `py-1 pl-3`, 12 / 12 / 13) are the strings; QuickAdd composes them through `personPill` / `personPillIcon`. - **Every component has a story file next to it** (`name.stories.tsx`) covering its states. Tracking ids (R1-nn, GAPS #nn) go in the file's `meta.tags` (`["r1-09", "gaps-22"]`), and on a story only when that story is the one answering that id (R17-13); never in story names. **Story names are short** (R17-21, George 2026-10-21): "State · qualifier", 40 characters at most ("Details · past due", "Logo dialog · wrong file refused"); the sentence that explains it is the story's `/** … */` (the docs page shows it as the story's description). **A story named for a behaviour has a play** (R17-12); the `play-fn` tag marks it, so no "Play ·" prefix. A play derives what it expects from the fixture data (`rows.filter(…).length`, not "3 partners") and finds a cell by its `data-slot` or role, not its column position, so a fixture or column change doesn't break it for nothing.
- **A part with many switches gets a Recipe, never a story per combination** (R20-24, George 2026-10-31: *"easy to find how to make new variations vs creating a story for every single one"*). One *Recipe* story whose controls are the capability switches on one fixture, with `parameters.docs.source.transform` writing the code block **from the args** (what a reader flips is what they copy — never the render's JSX); one story per capability with its play (the same fixture, one switch on); one story per state no switch shows (loading, empty, error, phone width); and an `.mdx` beside the stories (`<Meta of={Stories} />` replaces the autodocs page) with a "How to make one" section — the column/option table and a 20-line example. A Recipe switch that shares a name with a real prop (`expandable` as a boolean) spells out its `argTypes` (control, type summary) and scopes `controls.include` to the switches, or it inherits the prop's docgen type and an object control. First on `display/data-table.mdx`.
- **A line's weight follows what it separates** (George 2026-10-28). The outer the boundary, the stronger the line; choose by meaning, never by look. Region (`--border`): the bar from the page, a form from its actions (FlowFooter, FormFooter). Group (`--divider-tint`): sections within one form or panel (FormSection's rule). Row (`--divider`): items within a list (Item, table and menu rows). `Separator level="region" | "group" | "row"` says it in code. Two boundaries at different levels never share a weight.
- **Story scaffolding stays out of components** (George 2026-10-28). Anything a story needs that the UI doesn't (a stand-in slot, a frame, sample data, a stub link, a size readout) is a story helper in `src/stories/` or data in `src/fixtures/`, never a prop, mode or default content on a real component. Components take only what a screen passes them; a story fills the slots with helpers or fixture data. Helpers are story-only: not exported, not in the catalog, no story of their own — the one exception is `Foundations › Wireframes` (George 2026-10-30, G-03), which documents how Wireframes are drawn, not the helpers as components. A layout story fills slots with `Placeholder`: `label` names the slot, `detail` says what matters about it, `measure` shows its rendered width × height live, so the story answers "what does this slot get at this viewport?". Placeholders are plan cells by default (ORGANIZATION §11; George 2026-10-30): Guides' hairlines past the corners with a mark on each crossing, so a Wireframe reads as a drawing.
- **Doc comments.** Each exported component has a one-line `/** purpose */` directly above its function (the docs page description and the catalog's "I need…" column), and every prop on forms, patterns, shell, vault, primitives and templates has a `/** … */` comment (the props table).

Area-toned utilities (`bg-area`, `text-area-ink`, `bg-area-tint`, `bg-area-wash`, `border-area`, Eyebrow/Badge `tone="area"`) read CSS variables set by the nearest `[data-area="…"]` ancestor (`theme.css` layer 5): AreaPage sets it on the page, AreaTile and AreaIcon on themselves, Badge and FactItem through an `area` prop. A story that renders a popover open (`defaultOpen`) carries the literal tag `"!autodocs"`: an open Radix Select locks page scroll, so docs pages never mount one open; the open state shows in single-story view. - **Types belong to the component** (R13-02, George 2026-10-20). Every public component exports the type of its props (`XProps`; where the props are written inline, `type XProps = ComponentProps<typeof X>` at the file's foot) and of its data (`DagNode`, `PersonRow`, `AdminMetric`, `ListFilter<Row>`…). Screens connect the API's generated types to these structurally: `satisfies` (`pulse.metrics … satisfies AdminMetric[]`), `Pick` or a derived type, never a hand-written mapper where the shapes already line up; where they don't, one typed adapter per feature, next to its screen (`apps/web/features/<feature>/adapters.ts`). A wire change then fails the typecheck at the one adapter or `satisfies`, not in a component. The list of what the API still owes is `API-NEEDS.md` at the spike root (R13-01).

## How to add…

- **A base component.** Never mid-build, and never while the servers run (R12-02, GAPS #121). The procedure: (1) stop Storybook and the app (an agent asks whoever started them; it never stops a server it didn't start), (2) `npm run ui:add -w packages/ui -- <name>`, (3) `npm ci` from the spike root (a clean install from the lock file, so nothing half-reified survives), (4) start both again. `ui:add` refuses while either answers on 6106 or 3105 and prints these steps (`STORYBOOK_URL` names another worktree's Storybook, as it does for `run-plays` and `catalog`: a different tree's server holds a different `node_modules`). An agent that needs a base mid-build stops and reports instead. The script itself (R2-39): It runs the pinned shadcn CLI non-interactively (R9-05: `--yes --overwrite`, then every file that existed before, any base and `theme.css`, is put back and reported as a would-overwrite, with the CSS variables the CLI wanted listed for mapping onto Paige tokens; `--replace-existing` keeps the registry's version of existing bases on purpose). `components.json` points the `ui` and `hooks` aliases at `@/base`, so files land in `src/base`, `use-mobile.ts` included. **Stop Storybook and the app first** (GAPS #111): the CLI installs npm packages, and on Windows a reify with dev servers holding files can strip `node_modules`. It then rewrites the imports the registry and CLI write (`"cn"`, `@/lib/utils`, `@/base/…`, `@/registry/…/ui/…`) to relative paths, removes the unrelated `cn` npm package the registry lists, and runs the typecheck. Then add `src/base/<name>.stories.tsx` (shows in Base) and do not edit the file otherwise. `check:layers` fails on any `@/` or `"cn"` import left in the package (the package's own tsconfig resolves `@/`, but Next, transpiling the package, reads it as the app's src).
- **An npm dependency.** Read `STACK.md` first: a new library takes a row (the job, what it excludes) or `check:deps` reports it `UNLISTED`; a library the ledger rules out is `EXCLUDED` even transitively. Install from the spike root with `-w packages/ui`. Then **bounce the Storybook before any play run** (REVIEW-20, Round D step 1): Vite's dep cache keeps serving the old pre-bundle after a version change, every story that imports the package throws `does not provide an export named …`, and `run-plays` waits on them rather than failing.
- **After any re-add or shadcn bump.** `npm run ui:diff-base -w packages/ui` (R2-41) compares every `src/base` file with a fresh registry copy (imports rewritten the same way); `--full` prints the diffs. The Paige layer reaches into some bases with `data-slot` selectors (Progress, Select's native form over the NativeSelect base, Callout over the Alert base); a story per wrapper is the visual tripwire, this is the textual one. All 22 bases matched the registry on 2026-10-18.
- **A Paige component.** `src/components/<group>/<name>.tsx` (actions, inputs, display, feedback, navigation, overlays) wrapping the base: the variants a screen needs, named; defaults safe; a typed API. A one-line `/** purpose */` above the function, a header comment for the decisions. Story file next to it. A control a Field can host calls `useFieldControl` (`components/internal/field-context.tsx`). Then `node scripts/check-exports.mjs --write` and the app imports `@paige/ui/components/<group>/<name>`.
- **A form piece or field.** Patterns in `src/forms`, value-shaped fields in `src/forms/fields`, their helpers in `src/forms/internal`; copy in `forms/messages.ts`. A field reports its error through `useFieldError` (`forms/internal/field-support.tsx`) so its Field sees it.
- **A piece built from components.** The lowest section that fits: generic → `src/patterns`, app chrome → `src/shell`, Paige domain → `src/vault`. Prop doc comments on every prop; a story per state.
- **A primitive or template.** Arrangers go in `src/primitives`, page frames in `src/templates`. A new template is a foundation change: ask first.
- **A domain form.** `apps/web/features/<feature>/forms/<thing>-form.tsx`, built from Forms; the route composes the template and the form.
- **A chart kind.** In `src/charts`, over the chart base, with tokens (`--chart-*`), the hidden data table, loading and empty states; pages reach it through `lazy-chart.tsx` only.
- **A folder.** Add it to `TIERS` (or `FREE`) in `scripts/check-layers.mjs`, `SECTIONS` in `.storybook/main.ts`, `storySort` in `preview.tsx`, `PUBLIC` in `scripts/check-exports.mjs`, `SECTIONS` in `scripts/catalog.mjs` and an `@source` line in `theme.css`; restart Storybook.
- **A story.** `<name>.stories.tsx` next to the component, `meta` with `component` and no `title` (the folder decides). The title is the file name in PascalCase. Run `npm run catalog -w packages/ui` afterwards and commit the CATALOG.md change.
- **Anything from elsewhere** (a shadcn/ui block, a component from another registry, a legacy webapp page, a prototype screen): `INTAKE.md` at the spike root (draft 2026-10-30), six steps with a checkpoint each: Briefed → Named (the intake table) → Framed (the Wireframe, before content) → Landed (`labs/`, `@from` header) → Conformed (`npm run check` clean, level 1) → Approved (plays, walked, level 2). Third-party registry items never land in `src/base`: `npm run ui:intake -w packages/ui -- <url>` (`scripts/ui-intake.mjs`) fetches the item's JSON into `src/labs/intake/<name>/` with an `@from` stub, installs nothing, and never prints the URL (shadcn.io carries the account token in it; manned sessions only — INTAKE § Per-source notes). `--from-file <path outside the repo>` reads the URL or token from a file so it never passes through chat. `check:tokens` counts `labs/intake` as upstream until Conform.

## Traps

- **`git add -f`.** The repo `.gitignore` ignores `packages/` (a NuGet rule), so new files here are silently untracked. Stage source with `git add -f packages/ui/<path>`; never add `node_modules` or `storybook-static`.
- **Next dev cache.** After renames or CSS changes the app's dev server (Turbopack) can keep replaying an old module or CSS error from `apps/web/.next/dev` even though the code is fixed. Stop the server, delete `apps/web/.next/dev`, start it again. Do not stop a server someone else started; ask.
- **Storybook config changes** (`.storybook/main.ts`, folder renames, R7's moves) need a Storybook restart; until then its `index.json` can list files that no longer exist or miss whole sections.
- **A new folder's classes may not compile until Storybook restarts.** Tailwind's Vite scanner picked up a new file in an existing folder but not the first file in a new one (`src/labs/auth/`, 2026-10-30): the story rendered, the index listed it, but a class used only there (`*:flex-1`) had no rule. If a utility has no effect and the class is on the element, restart before debugging the CSS.
- **MDX is CommonMark; tables need `remark-gfm`** (George 2026-10-30). Storybook's MDX compiler has no GitHub-flavoured markdown of its own, so a pipe table in `src/docs/*.mdx` renders as running text with the pipes in it. `.storybook/main.ts` passes `remark-gfm` to `@storybook/addon-docs` (`mdxPluginOptions.mdxCompileOptions.remarkPlugins`); keep it when the addon config changes. The markdown in story and component comments is rendered by `markdown-to-jsx`, which has tables on its own; this is only about `.mdx` files.
- **New story file, classes missing in the running Storybook.** Tailwind's dev scan doesn't always pick up a brand-new file under `@source`, so its new classes render unstyled until the CSS entry is reprocessed. `touch packages/ui/.storybook/preview.css` (no content change) and reload; no restart needed. The static build is unaffected.
- **Storybook's index keeps a transient parse error** (R13-16, GAPS #128). After a file under `src` is edited in place mid-write (a `sed -i`, a script), `index.json` can answer "Unable to index … Could not parse import/exports with acorn" (text, not JSON) even though the file is fine: the indexer read it half-written and cached the failure. Fix: `touch` the file (no content change); the index comes back without a restart. Editing through the editor or a write-then-rename avoids it.
- **The app's dev server serves a stale module on the server** (R13-16, GAPS #134, #116): a hydration mismatch whose server half is old code (a prop that no longer exists), or an error that was fixed, replayed from `apps/web/.next/dev`. curl still answers 200. Fix: whoever started the server stops it, deletes `apps/web/.next/dev`, starts it again; anyone else verifies on their own `next build` + `next start` on another port and stops it by PID afterwards.
- **Story titles use an experimental hook** (R2-47, GAPS #87). `.storybook/main.ts` wraps the CSF indexer through `experimental_indexers` to PascalCase the file name in auto titles. Re-check it on every Storybook upgrade. If it breaks, the fallback is PascalCase story file names (or `title:` lines back), which keeps the story ids.
